# 携程西藏景点评论采集工具 · 使用说明（最终版）

> 目标：现有 11,522 条 → **50,000+**
> 采集方式：调用携程公开评论接口（已实测可用、速度快、不受网页风控限制）

---

## 〇、结论先说：最终方案已跑通

经过实测，采集链路确定为：

```
① Edge 浏览器（带首页预热）→ 每个景点取一次真实 poiId + 景点信息
② requests 直接调携程评论接口 → 50 条/请求，多窗口去重
③ 解析成 15 字段 CSV → 按评论编号与现有数据合并去重
```

### 实测数据（已验证）

| 项目 | 结果 |
|---|---|
| 接口 | `POST https://m.ctrip.com/restapi/soa2/13444/json/getCommentCollapseList` |
| 是否需要 Cookie | **不需要** |
| 是否受网页风控影响 | **不受**（网页版会被滑块拦截，接口不会） |
| 每页条数 | **50 条**（给 100 也只返回 50） |
| 分页硬上限 | offset ≤ 3000 → 每窗口最多 **3,050 条**（50×61 页） |
| `sortType` | **6=推荐**，**1=最新**（3/4/5/7/8 与 1 相同），2=另一种排序 |
| `starType` | **0=全部**，**1~5=对应星级**（精确分区、互不重叠） |
| 布达拉宫 | 网页只能翻 3,000 条，**接口池 10,399 条**（1★350+2★79+3★217+4★599+5★9154） |
| 纳木措景区 | 网页 3,000，**接口池 3,950** |
| 雅鲁藏布大峡谷 | 网页 3,000，**接口池 4,160** |
| 八廓街实测 | 采到 **347 条**，其中 **181 条全新**，166 条与现有重复（编号精确匹配 ✔） |

**关键收益**：低星窗口（1~4 星）总量都远小于 3,050，**可以 100% 拿全**；5 星窗口拿满 3,050；再用「推荐/最新/排序2」多窗口叠加，**单景点可采量远超网页的 300 页上限**。

## 二、三步跑完

### 第 1 步：准备景点清单 `spots.txt`

格式：`景点名,景点URL`，每行一个。已有 14 个示例，**要抓哪些就往里加**。

```powershell
# 想批量补清单，先跑这个（用浏览器读携程西藏景点列表）
python ctrip_tools.py discover --pages 60
# 产出 data/out/景点清单_携程.csv（景点名 + URL + 点评数），挑出来复制进 spots.txt
```

### 第 2 步：采集（★核心命令）

```powershell
# 先试跑，确认链路正常（每个景点只抓第 1 页）
python ctrip_tools.py api --test --spot 八廓街

# 正式采集：脚本会自动开 Edge 取 poiId，再用接口翻页
python ctrip_tools.py api

# 只抓某个景点
python ctrip_tools.py api --spot 布达拉宫

# 只跑指定窗口
python ctrip_tools.py api --window 推荐-全部 --window 最新-全部
```

**运行特征**
- 会弹出 Edge 窗口，**自动**逐景点取 poiId（约 3 秒/景点），不要手动关
- 如果弹出滑块验证：**手动拖一下即可**，脚本会继续（凭证存在 `_edge_profile`，后续一般不再拦）
- **断点续跑**：中断后重跑同一条命令，已采的评论编号会自动跳过
- 中途日志示例：
  ```
  [推荐-全部] 新增 3050 条（累计 3050）
  [最新-全部] 新增 980 条（累计 4030）
  [推荐-5星] 新增 420 条（累计 4450）
  ```
- 采集进度实时写入 `data/out/采集进度.csv`

**速度**：约 1.5~2 秒/请求、50 条/请求 → **每 1 万条约 6~8 分钟**。3.8 万条约 30~50 分钟。

### 第 3 步：解析 + 合并去重

```powershell
python ctrip_tools.py parse
```

产出（都在 `data/out/`）：

| 文件 | 内容 |
|---|---|
| `新抓取_去重.csv` | 本次抓到的全部评论（按评论编号去重） |
| `合并_总表.csv` | **你的最终数据集**：现有 11,522 条 + 新数据，按评论编号去重，15 列、UTF-8 BOM |
| `景点实测清单.csv` | 每个景点：已抓到 / 携程显示点评数 / 地址 / 开放时间 / 电话 |
| `采集进度.csv` | 每个景点：接口池大小 / 已采集 / poiId |

屏幕会打印：现有多少条、**真正新增多少条**、重复多少条、缺编号/缺日期/缺评分条数。

## 三、15 个字段的来源（与原数据集格式逐一对应）

| 字段 | 来源 | 格式验证 |
|---|---|---|
| 景点名称 | spots.txt 的清单名 | ✔ |

## 五、常见问题

**Q1：弹出滑块验证怎么办？**
手动拖一下即可，脚本会继续。凭证会存进 `_edge_profile`，后面基本不再出现。**不要把 `headless` 改成 True。**

**Q2：中途断了？**
重跑同一条命令。已写入 `api.jsonl` 的评论会自动跳过。

**Q3：某景点只采到几十条，但携程显示几万条？**
正常。接口池（`totalCount`）才是真实可采量，网页显示的"X万条点评"包含聚合来源。看 `采集进度.csv` 的"接口池"列。

**Q4：会不会被封？**
接口版不受滑块风控影响，但仍建议：保持默认间隔（0.8~1.8 秒/请求）、分批跑、别改并发。

**Q5：只想抓差评？**
改 `ctrip_tools.py` 里的 `API_WINDOWS`，只保留 `(6, 1, "推荐-1星")` 这类低星窗口。1~4 星都能 100% 拿全。

**Q6：解析规则改了要重抓吗？**
不用。`data/raw/*/api.jsonl` 是原始接口数据，重新 `parse` 即可。
