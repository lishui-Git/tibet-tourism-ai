# 数据库设计说明

**项目名称**：基于 DeepSeek 的西藏旅游景点智能评价与分析系统
**文档版本**：V1.1（按精简要求收敛表数量）
**编制日期**：2026-09-20
**数据库**：MySQL 8（`localhost:3306`），库名 `tibet_review`，字符集 `utf8mb4`
**上游依据**：`数据采集/旅游评论数据集_最终版.csv`（**实际字段已全量核验**）、`开题/业务需求文档.md`（V1.1）、`docs/design/详细设计说明书.md`

> **设计资料来源声明**：`spot` 与 `review` 两张**核心旅游数据表**严格依据最终数据集的 15 个真实字段设计，字段名、类型、可空性均来自对 59,033 行的全量核验结果；`sentiment`、`aspect`、`topic`、`stat_*`、`spot_report`、`qa_record` 等表属于**后续分析结果与业务数据**，在核心表基础上扩展。**不存在脱离 CSV 凭空设计的数据表。**

### 0.1 表数量精简（V1.1 变更）

原设计 21 张表，对本科毕设略显偏重，按精简要求**收敛为 17 张**（净减 4 张）。**精简原则：只合并"同一语义族"的表，不把不同语义的数据强行并入宽表。**

| 决策 | 处置 | 理由与信息去处 | 是否影响功能 |
|---|---|---|---|
| **D-1** | 删除 `ml_model` | 模型版本与实验信息属**任务执行结果**，并入 `analysis_task`：新增 `model_type`／`model_version`／`model_path`／`random_seed`／`model_metrics_json`（含训练样本量与 accuracy/precision/recall/f1/混淆矩阵）；论文"实验结果"章节直接引用该任务记录 | ❌ 不影响。版本、路径、随机种子、指标全部保留 |
| **D-2** | 删除 `llm_failure` | 失败原因与重试信息**本质是日志**，并入 `task_log`：`level=WARN/ERROR` ＋ 新增 `ref_key`（关联 comment_id／spot_id）／`retry_count`／`resolved`；失败原因写入 `message`，场景写入 `stage` | ❌ 不影响。失败定位与补跑能力保留（`idx_tl_failed` 索引支持"查未补跑的失败"） |
| **D-3** | 删除 `clean_log`，与 `task_log` 合并 | 原 `clean_log` 只有"步骤名＋四类计数＋说明"，与 `task_log` 字段高度重叠，属重复日志体系。现统一由 `task_log` 承载：`stage=清洗步骤名`，四类计数（input/output/dropped/abnormal）放入新增字段 `detail_json` | ❌ 不影响。清洗各步骤处理量仍可逐条复核 |
| **D-4** | 删除 `spot_comparison` | 对比指标（评论量／均分／好评率／评分分布／情感分布／图文率／方面对比）**由后端实时查询** `stat_spot`／`sentiment`／`aspect` 计算；DeepSeek 生成的对比解读**直接返回前端**，不落库 | ❌ 指标对比不受影响（本身不依赖模型）；⚠ 对比解读每次需调用模型，**同一景点对被反复对比时会产生重复调用** |
| **D-5** | **保留 `spot_fact_package`** | 它是景点智能评价的**唯一数据依据与可追溯链路**（FR-IE-07）。评价文本必须能回查到"当时依据的数字快照"，否则"数据负责事实"无法验证 | — 明确保留 |
| **D-6** | **保留 `stat_overview`**（你给的候选清单未列，此处说明理由） | **定位为"离线预计算的全局统计汇总表"，不作为独立事实源**——其全部字段均由 `spot`／`review`／`stat_spot`／`stat_time`／`stat_ip` 确定性聚合得出，由离线任务生成、可随时重算。保留的作用是：① **减少重复聚合**（数据总览页与问答的 `DATA_METRIC` 类型都要读"评论总数／景点总数／数据起止日期／有效 IP 样本数／可完整评价景点数"，集中预计算可避免每次重复扫描明细表）；② **保证总览指标口径一致**（避免各接口各自聚合导致数值不一致）。表内仅 **1 行数据**，不含任何独立语义 | ❌ 不影响。**本表不承担"事实源"职责**——所有数值以明细表为准，本表仅供查询复用 |

> **表数量已冻结为 17 张**：本节记录的 D-1～D-4 为已完成的精简，D-5／D-6 为保留决策。**后续不再继续压缩表数量**；如因开发需要调整，须先更新本文档与 `ER图.md`、`建表脚本.sql` 并保持三者一致。

**关于 D-4 的补充说明**：`spot_comparison` 的删除是按你的要求执行，**未以"成本控制"为由申请保留**。原因：该内容每次调用约 900 tokens，属用户主动触发、低频操作，且景点对组合随机性大、真实重复率低，**缓存收益有限**；相比之下 `spot_report` 的预生成才是成本控制的关键（57 个景点、必然被反复查看）。因此**按你的决定删除**。若后续实测发现热门景点对被频繁对比导致调用量偏高，再考虑恢复——届时本文档需同步更新。

## 1. 设计原则

| # | 原则 | 说明 |
|---|---|---|
| 1 | **评论级与景点级严格分离** | CSV 后 4 个字段（地址／开放时间／官方电话／景点介绍）在同一景点内完全重复，必须拆入 `spot` 维表，不得留在 `review` 表（BR-09） |
| 2 | **事实与解释分离** | 由系统计算的指标存 `stat_*`；模型生成的文本存 `spot_report`、`qa_record`。二者不混表 |
| 3 | **多方法结果并列** | 情感结果存在 DeepSeek／MLlib／词典法三种来源，用 `method` 区分而非建三张表 |
| 4 | **幂等写入** | 结果表均设计唯一键，支持 `INSERT ... ON DUPLICATE KEY UPDATE`，保证批处理断点续跑不产生重复行（NR-R-01／02） |
| 5 | **可追溯** | 评价报告关联事实包版本与任务号；事实包存快照 JSON |
| 6 | **不建无意义表** | 不建权限表（权限从简）、不建用户画像表（无用户行为数据）、不建推荐相关表、不建实时表；**同一语义族不拆多表**（见 §0.1） |

## 3. 核心数据表详细设计（来源：最终数据集 CSV）

### 3.1 `spot` — 景点维表

**来源**：CSV 的「景点名称」列去重后得到 837 个景点；「地址」「开放时间」「官方电话」「景点介绍」4 个景点级字段取每个景点的代表值；「来源口径」来自 `数据采集/景点来源标注.csv`。

| 字段名 | 类型 | 允许空 | 键 | 说明 | 实测依据 |
|---|---|---|---|---|---|
| `spot_id` | INT UNSIGNED AUTO_INCREMENT | 否 | PK | 景点主键 | 系统生成 |
| `spot_name` | VARCHAR(128) | 否 | **UK** | 景点名称 | CSV 景点名称，837 个唯一值 |
| `source_scope` | VARCHAR(16) | 否 | IDX | 来源口径：`tibet`／`route` | 西藏 554／沿线 283 |
| `address` | VARCHAR(255) | 是 | | 地址 | **837/837 有值** |
| `open_time` | VARCHAR(255) | 是 | | 开放时间（原始文本，如"全年全天开放"） | **546/837 有值** |
| `phone` | VARCHAR(64) | 是 | | 官方电话 | **仅 99/837 有值** |
| `introduction` | TEXT | 是 | | 景点介绍 | **738/837 有值** |
| `poi_url` | VARCHAR(255) | 是 | | 携程景点页地址（可选，便于溯源） | 采集阶段已知 |
| `review_count` | INT UNSIGNED | 否 | IDX | 评论量（冗余，便于排行，来源 `stat_spot`） | 837 个景点，中位数 5 |
| `has_full_evaluation` | TINYINT(1) | 否 | IDX | 是否具备完整智能评价资格（评论量 ≥100） | **57 个为 1** |
| `created_at` | DATETIME | 否 | | 入库时间 | — |

**索引**：`PK(spot_id)`；`UK(spot_name)`；`IDX(source_scope)`；`IDX(review_count)`；`IDX(has_full_evaluation)`

**说明**：`open_time`／`phone` 可空是**如实反映数据现状**（缺失即 NULL），系统按 FR-SA-01 不展示空字段，**不做占位造数**。

### 3.2 `review` — 评论明细表

**来源**：CSV 的 11 个评论级字段，共 59,033 行。

| 字段名 | 类型 | 允许空 | 键 | 说明 | 实测依据 |
|---|---|---|---|---|---|
| `comment_id` | BIGINT UNSIGNED | 否 | **PK** | 评论编号 | **59,033 条、唯一率 100%**（天然主键，无需自增） |
| `spot_id` | INT UNSIGNED | 否 | FK→`spot`、IDX | 所属景点 | 由景点名称映射 |
| `score` | TINYINT UNSIGNED | **是** | IDX | 评分 1–5 | **37 条空值** |
| `score_desc` | VARCHAR(16) | **是** | | 评分描述 | 37 条空值，与评分一一对应 |
| `content` | TEXT | **是** | | 评论内容 | **1 条空值**；含长文本，最长 1,829 字 |
| `content_length` | SMALLINT UNSIGNED | 否 | | 正文字数（系统计算） | 中位数 31 字 |
| `publish_date` | DATE | 否 | IDX | 发布时间 | 格式统一，异常 0 条 |
| `publish_year` | SMALLINT UNSIGNED | 否 | IDX | 发布年份（拆分，便于统计） | 2015–2026 |
| `publish_month` | TINYINT UNSIGNED | 否 | IDX | 发布月份（拆分） | 1–12 |
| `ip_location` | VARCHAR(32) | 否 | IDX | IP 归属地（标准化后） | 66 种取值；"未知"占 40.70% |
| `ip_is_unknown` | TINYINT(1) | 否 | IDX | 是否为"未知" | **2022-08 前 100% 为 1** |
| `ip_province` | VARCHAR(32) | 是 | IDX | 标准化省份（用于客源地统计） | 仅 `publish_date ≥ 2022-08-01` 有效 |
| `user_nick` | VARCHAR(128) | 否 | | 用户昵称（**非稳定 ID，不用于建模**） | 32,532 个；"匿名用户"占 5,972 |
| `like_count` | INT UNSIGNED | 否 | IDX | 点赞数 | 非零 18.35%，最大 588 |
| `image_count` | TINYINT UNSIGNED | 否 | | 图片数 | 非零 48.35%，最大 18 |
| `image_urls` | TEXT | 是 | | 图片URL（原始以全角"，"分隔） | **30,493 条为空＝该评论无图**，非缺失 |
| `is_low_info` | TINYINT(1) | 否 | IDX | 是否低信息量（正文 ≤10 字） | **10,228 条（17.33%）** |
| `is_dup_content` | TINYINT(1) | 否 | IDX | 正文是否与其他评论完全相同 | **4,239 条（7.18%）** |
| `dup_group_id` | INT UNSIGNED | 是 | IDX | 重复组号（对应 `内容重复清单.csv`） | 1,285 组 |
| `created_at` | DATETIME | 否 | | 入库时间 | — |

**索引**：
- `PK(comment_id)`
- `IDX(spot_id)`、`IDX(publish_date)`、`IDX(spot_id, publish_date)`（统计聚合主用）
- `IDX(ip_province)`、`IDX(publish_year, publish_month)`、`IDX(like_count)`
- `IDX(is_low_info)`、`IDX(is_dup_content)`、`IDX(dup_group_id)`
- `IDX(score)`、`IDX(ip_is_unknown)`

> 以上 11 个索引 ＋ `PK(comment_id)` 与 `建表脚本.sql` 中 `review` 的实际定义一致。

**设计要点**：

| # | 要点 | 理由 |
|---|---|---|
| 1 | `comment_id` 直接作主键，不用自增 ID | CSV 中该字段唯一率 100%，天然主键；直接用它作幂等键，与上游完全一致 |
| 2 | `score`／`content` 允许为空 | 如实反映 37 条缺评分、1 条缺正文的现状；统计时按"未判定"单列，不伪造填补 |
| 3 | 时间字段冗余 `publish_year`／`publish_month` | 避免每次统计都做函数运算，提升 GROUP BY 性能 |
| 4 | `ip_province` 与 `ip_location` 并存 | `ip_location` 保留原值便于溯源；`ip_province` 为标准化结果，仅 2022-08 后有效（BR-01） |
| 5 | `image_urls` 为空是业务含义（无图），不是数据缺失 | 前端据此显示"无图片"，不报缺失 |

### 8.2 外键与级联策略

| 外键 | 策略 | 理由 |
|---|---|---|
| `review.spot_id → spot.spot_id` | `ON DELETE RESTRICT` | 景点不允许被删除；评论是基础数据 |
| `sentiment.comment_id → review.comment_id` | `ON DELETE CASCADE` | 评论删除则结果无意义 |
| `sentiment.spot_id → spot.spot_id` | `ON DELETE RESTRICT` | 冗余字段，保持一致 |
| `aspect.comment_id → review.comment_id` | `ON DELETE CASCADE` | 同上 |
| `spot_report.spot_id → spot.spot_id` | `ON DELETE CASCADE` | 景点删除则报告失效 |
| `qa_record.user_id → sys_user.user_id` | `ON DELETE SET NULL` | 用户删除后保留问题记录，仅匿名化 |
| `task_log.task_id → analysis_task.task_id` | `ON DELETE CASCADE` | 任务删除则日志一并清理 |
| `analysis_task.operator_id → sys_user.user_id` | `ON DELETE SET NULL` | 触发人注销后保留任务记录 |

> **实践提示**：批处理批量导入时建议**临时关闭外键检查**（`SET FOREIGN_KEY_CHECKS=0`）以提升写入速度，导入完成后立即恢复并做一致性校验。

| M5 智能问答 | `stat_spot`、`stat_time`、`stat_ip`、`aspect`、`spot_report`、`qa_record` | 检索已有结果 ＋ 存记录 |
| M6 系统管理 | `sys_user`、`analysis_task`、`task_log` | 用户、任务、统一日志（含模型实验信息与失败记录） |
| 离线清洗 | `spot`、`review`、`task_log` | CSV → 表；清洗统计写入 `task_log.detail_json` |
| 离线统计 | `stat_*`、`topic*`、`sentiment(mllib)`、`analysis_task` | Spark 产出；模型版本与指标记入 `analysis_task` |
| 离线语义 | `sentiment(deepseek)`、`aspect`、`comment_semantic`、`task_log` | DeepSeek 批处理产出；失败记入 `task_log` |

**反向核对**：`spot`／`review` 的每个字段都能在 CSV 中找到来源（§3）；**本设计共 17 张表**（§2 表清单），每张表都能被某个功能使用；**不存在无功能使用的表，也不存在无表支撑的功能**。
