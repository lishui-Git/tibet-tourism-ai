**系统架构分层（依据开题报告第 66-74 行 + C4 文档）：**
```
应用与展示层   Flask + ECharts（5 个核心模块页面 + 登录与权限）
     ↓
景点智能评价与对比解释  系统构造事实包 → DeepSeek 生成（数据负责事实，模型负责解释）
     ↓
结构化存储层   MySQL 8（17 张表）
     ↓
DeepSeek 语义理解层   Python + DeepSeek API（情感/强度/方面/关键词/摘要）
     ↓
Spark 离线分析层   Scala + Spark 3.3.1（Spark SQL 聚合 + MLlib 情感基线 + LDA 主题）
     ↓
数据清洗与预处理层   Python（字段规范化、评论级/景点级拆分、低信息量与重复标记）
     ↓
数据层   旅游评论数据集_最终版.csv（59,033 条，唯一数据源，原数据不覆盖）
```

**核心业务流程（数据从输入到展示）：**
1. 原始评论数据经**数据清洗与规范化**进入 Spark 离线统计分析；
2. Spark 得到景点/时间/客源地维度统计指标、MLlib 情感分类基线、LDA 主题结果；
3. 进入 **DeepSeek 评论语义理解**，得到情感、情感强度、评价方面、关键词与摘要等结构化结果；
4. 上述结果**统一存入 MySQL**；
5. 系统在已有结果基础上**构造景点事实包**（统计指标 + 情感与方面结果 + 代表性正负面评论）；
6. 事实包分别用于**景点智能评价**、以及**景点对比**与**限定范围智能问答**；
7. 均由 DeepSeek 在**给定事实的约束下**生成自然语言内容，最后经 Flask 接口由 ECharts 前端呈现。

### 4.6 主要功能模块之间的关系

**五个核心模块（开题报告第 29-34 行）：**
1. **数据总览模块** —— 评论数据的清洗、规范化与多维度统计
2. **景点分析模块** —— 单景点统计指标、情感与主题分析
3. **景点智能评价模块** —— DeepSeek 评论语义理解与景点事实包生成
4. **景点对比模块** —— 结构化对比与 DeepSeek 对比解释
5. **智能问答模块** —— 限定范围内的基于评论数据的问答

> **依赖关系**：模块 1 是数据基础 → 模块 2 提供统计与语义结果 → 模块 3 依赖模块 1、2 的结果构造事实包 → 模块 4、5 复用模块 3 的事实包机制。
> **项目的核心特色（`产品审查报告.txt` 结论）**：价值不在"又做了一个旅游网站"，而在
> **「评论 → 可追溯的景点评价」这条链路的可控性** —— 每一层都可回查，模型只做"基于已检索事实的自然语言解释"。
