## 0. 已探明的事实（不要再重复验证）

| 结论 | 数值 | 影响 |
|---|---|---|
| 每页评论数 | **10 条** | 页数 × 10 = 条数 |
| 单窗口分页上限 | **300 页（硬顶，"下一页"置灰）** | **单窗口最多 3,000 条** |
| 「最新」排序 | 严格按时间倒序 | 布达拉宫第 300 页 = **2024-06-10** → 只覆盖最近约 2.2 年 |
| 「推荐」（默认）排序 | **日期乱序、偏向近期** | 实测翻 7–8 页（70–80 条）仅 1 条 2019 年 → **唯一能摸到历史的通道，但老评论稀疏** |
| 筛选窗口 | **独立计算 300 页** | 「差评」只有 431 条 → **43 页，可 100% 拿全** |
| 布达拉宫线上总数 | **22,411**（好评 9,805 / 消费后 13,359 / 差评 431） | 采集完成度仅 **2.0%** |
| 纳木措景区线上总数 | **5,902** | 完成度 7.6% |
| 雅鲁藏布大峡谷线上总数 | **4,933** | 完成度 9.1% |
| 八廓街线上总数 | **1,162** | 完成度 **14.5%** |
| 纳木措圣象天门 / 文成公主剧场 | 330 / 109 | 完成度 94% / 96%（长尾已抓满，无空间） |

**核心公式**

```
单景点可补量 ≈ min( 线上点评总数 , 300页 × 10条 × 有效窗口数 ) − 与现有数据的重叠量(按评论编号去重)
双窗口（推荐 + 最新）去重后实测 ≈ 3,900 ~ 5,100 条 / 景点（大景点）
止损规则：某窗口新增条数 < 该窗口总量的 20% → 不再开第 4、5 个窗口
```

## 1. 执行规则（每个景点都一样，照做即可）

### 1.1 抓取窗口顺序

| 顺序 | 窗口 | 页数上限 | 必抓？ | 目的 |
|---|---|---|---|---|
| ① | 全部 × **推荐** | 300 | **必抓** | **唯一能拿到 2019–2022 老评论的通道**，稀缺，先锁住；翻到底即自动得出该景点"线上可浏览总数" |
| ② | 全部 × **最新** | 300 | **必抓** | 拿 2024-06 至今的全量 |
| ③ | **差评** × 最新 | 45 | **必抓** | 差评全量（布达拉宫仅 431 条），情感分析价值最高 |
| ④ | 好评 × 最新 | 300 | 条件触发 | 仅当 ①②③ 新增 ≥ 预估新增时才开 |
| ⑤ | 消费后评价 × 最新 | 300 | 条件触发 | 同上 |

> **先抓"推荐"再抓"最新"**：推荐窗口里的老评论是不可再生的稀缺资源。

### 1.2 去重与断点（铁律）

1. **主键 = 评论编号**，全局唯一，所有窗口的采集结果按它做差集入库。
2. 同一景点一旦中断，**从第 1 页整体重跑该景点的该窗口**（排序可能变动，300 页成本很低）。
3. 记录每条数据的 `page_no` 与 `crawl_time`，便于事后核查。
4. **现有数据里 2019–2023 的老评论必须原样保留**，不要因为"疑似重复"丢弃。

### 1.3 限速与合规

- 单线程，1–2 请求/秒，随机延时 2–5 秒；失败指数退避重试 3 次。
- 仅用于个人学术研究；遵守 robots.txt；论文中声明数据来源。

## 7. 已知局限（写进论文"数据与局限"章节）

1. **时间结构不均衡**：补抓后数据为"2023–2026 密集 + 2019–2022 稀疏"。"最新"排序只覆盖最近约 2.2 年（布达拉宫 2024-06 起），历史只能靠"推荐"窗口的稀疏老评论。
2. **单景点天花板**：受 300 页封顶，布达拉宫线上 22,411 条最多能获取约 3,000–5,000 条（13%–23%），**总量必须靠景点数量补，而不是单点深度**。
3. **显示总数 ≠ 可浏览数**：携程"条点评"可能含聚合来源，实际可翻页量以"最后一页页码 × 10"为准（八廓街 168/1,162 已是征兆）。
4. **IP 属地结构性缺失**：2022-08 之前的评论 100% 为"未知"（携程政策），客源分析须限定 2022-08 之后的数据。
5. **评分偏斜**：5 星占 74.9%，且个别景点（藏域星球天文体验馆 99% 五星）疑似异常，建模需做类别平衡与异常标注。
